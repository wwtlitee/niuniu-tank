### 复查出的阻断级缺陷

1. **P0-1 波次重入**（engine.js:3084 触发 / 2466 定义）
   `waveCleared()` 无一次性闸门，`setTimeout(900)+setTimeout(900)` 共 1.8s 内条件持续成立 → 每帧重复调用。
   取证（diag-wave.mjs 打点）：单次清波 waveCleared 调用 28 次、startWave 17 次，波次 1→17，score 600→16900，
   直接跨过 victoryWave=15。帧率越高越严重（真机 60fps 理论跳 ~100 波）。

2. **P0-2 敌人永远打不到门**（engine.js:1497 flowDirFor / 2969 啃咬分支）
   流场最小值是 1（大门格 T_BASE 被 passableForFlow 判不可穿），敌人在 d=1 处所有邻居 ≥2 → 被推离大门，
   在门口反复弹跳；啃门分支要求 `!moved`，弹跳时 moved=true → 永不触发。
   取证：挂机 150s 大门 600/600 零掉血、lives 3、score 0。**游戏不存在失败条件。**

3. **P0-3 流场与移动两套高度阈值打架**（engine.js:1489 用 1.2 判格心 / 1411 用 0.9 判五点采样）
   坡道格高度沿 x 插值（格内 0.733→1.467），流场只看格心 1.1 判"可通行"，规划出从坡口北侧直接上坡的路线；
   实际移动时四角采样点高 ≈1.23 > 0.9 被 blockedForTank 拒绝 → 敌人撞空气墙。
   叠加 turn 粒度问题：thinkTimer=1~2.6s 但 1 秒穿 1 格 → 过冲，在 x=17~20/row33 之间 d=15 处来回震荡。

### 关键结论

- 原审计"7/7 通过"不成立：33 秒烟测 + 只断言"无 console error"，没有一条结果断言；
  `lives:3` + `enemyCount 2→6` 不能证明敌人到达（150s 实测恰恰相反）。
- **现有所有平衡性数据作废** —— 都是在"敌人到不了 + 波次会跳"的状态下采的。
- 修复顺序：P0-1 闸门 → P0-2 到达判定 → P0-3 统一高度判据+按格重算方向 → 卡死兜底 → 烟改结果断言 → 最后才调平衡。
